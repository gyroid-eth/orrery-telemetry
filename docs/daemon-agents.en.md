# Canonical bindings and notifications for deterministic daemons

[Japanese source](daemon-agents.md). This local CLI is not deployed by the general installer. Run `<dev-python> <helper-release>/bin/agentstack-daemon`. Ordinary Claude/Codex profiles, proxy schemas and startup rituals remain unchanged.

Use a private orrery-mail-connection-v1 copy, with a UUID explicitly verified/pinned through enrollment inspect. Only literal loopback HTTP and http_bearer_mode=disabled are supported. HTTP health must advertise the same persistent server_instance_id as management inspect; older builds fail closed. There is no ambient credential or alternate URL fallback.

The parent checks a free canonical name through bound whois; the operator confirms its purpose/project. `create --connection CONNECTION --project-key PROJECT --name NAME --journal JOURNAL --operator` is a local operator-only, single-attempt command, never an MCP tool. It fsyncs a0600 journal before canonical register_agent (program=orrery-daemon, model=deterministic), verifies returned name/positive numeric ID/token, then saves its own credential exclusively. stdout contains only a non-secret receipt. The flag does not prove a human: this trusts the local OS user and an operator procedure.

Unknown/partial outcomes keep the same journal; never retry register, delete it, invent an alias or reuse an LLM identity. After canonical whois confirms the exact row, `finalize-create --connection CONNECTION --journal JOURNAL --agent-id ID --operator` verifies management UUID/row/name/project/retirement/fingerprint and HTTP UUID/row/program, then activates only the same journal credential. It never registers, claims, recovers or retires. Conflicts are refused; if the row cannot be confirmed, return to the operator. Models must not read the journal or credential.

The strict orrery-daemon-binding-v1 profile has exactly kind, name, agent_id, project_key, connection, peer_name, peer_id, pause_path and lock_path. The Japanese guide provides the full example. All paths are absolute; IDs are positive integers obtained from canonical responses. Files are0600 and private directories0700. `inspect --profile PROFILE` verifies without running the daemon.

Startup/every call verifies the current owner fingerprint/generation, persistent UUID on both transports, numeric daemon row/project/program and fixed peer. Generation changes stop the helper until operator verification/restart. HTTP redirects are refused. Current bundled read APIs without token arguments use the local-principal transport plus helper-side owner checks; arguments are never invented. This is not general per-owner Mail authorization.

Exports: call, wait_for_notification, close. Allowed calls: normalized runtime_status, fixed-peer whois, own fetch_inbox (up to1,000), ACK and fixed-peer send. Caller/project/token overrides, registration/enrollment/retirement, other inboxes and database/signal scanning are denied. Messages preserve sender_id/project_id; foreign messages are refused before ACK. Numeric Mail IDs are separate from Codex App session/subagent IDs.

Waiting reuses canonical agentstack-await-reply.wait_for_reply with authenticated bound metadata fetch and cancellation. It never ACKs/reads or copies bodies. Body fetches update only an ephemeral wait watermark, not a saved cursor/read state; restart resets it. A maximum60-second timeout returns control for catch-up. A full1,000-item window is not complete history. Duplicate waits/profile instances are refused.

Pause is checked at entry and before each network request, including metadata waits; in-flight cancellation is not guaranteed. close cancels the wait, awaits completion and releases its lock within4.5 seconds; HTTP/control timeouts are2 seconds each. Diagnostics expose only fixed codes, never credentials/bodies/free exception text. Synthetic bindings and isolated real-Mail processes are separate from live Keychain/launchd/Tunnel/public-release acceptance, which requires separate approval.
