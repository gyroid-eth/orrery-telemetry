# Caller fixture evidence

The five caller contracts use the product's fixed
`isolation/agentstack/clients/child_01/profile.json` layout, not an arbitrary
owner path or symlink alias. Native acceptance remains separate and red until
its real pinned-CLI adapter is supplied.

The caller adapter has a delivery-only binding for the five actual entry routes,
not completed R3/native acceptance.
It copies installer-declared files into an isolated install and checks the real
manifest inventory and source bytes. Its dedicated Python loads a fixture module
through its own site-packages `.pth` and replaces only
`runtime_native_scope.require_native_binding` (zero replacements when disabled).
It does not edit product source or the host interpreter, approve unverified
proposals, or replace owner/profile/source/R2 gates. Bootstrap success is not
real-entry argv/env delivery or native-enforcement evidence. Separate entry/R2
checks compare all five routes, including empty/nonempty MCP configuration.
Pending replay, native tool use, actual always-empty-MCP mutations and production
source-drift negatives remain incomplete; caller acceptance stays red. A real
ps failure remains a failed delivery/precondition, not a successful mutation or
native refusal. The native adapter is absent.

Each caller invocation owns a fresh real S2c prepared at the same literal
path/port, after verifying that the previous owned process exited. HTTP health
must match the new config's actual instance/generation/authority fields. A live
predecessor or stale health binding fails, and no environment exclusions beyond
the three literal execution keys are added. Resume's prior owner supplies only
the independently compared intent, not an authority wrapper for reuse. A real
configure/spawn/SessionStart/normal end must create its retained/session-index
precondition. The minimal transcript is fixture input, not native CLI evidence;
its separate capture/nonce/witness cannot stand in for the actual resume.
Binding-off resume enables only that legitimate preceding spawn, then requires
zero replacements and the real native refusal in the actual operation interval.
If the prerequisite fails (including real ps in a sandbox), the test stays red.

The operator adapter passes one complete canonical caller dict plus an explicit
fixed parent client to the real full-form API. Prepare-only must not start a
provider; its separate delivery comparison uses the existing foreground R2.
An ordinary operator execution also runs without the fixture execute helper,
and a stale admitted digest must fail before launch/window publication.
Sixteen single-field incoming-request controls leave the configured owner
unchanged and require a specific mismatch with no client-tree changes, including
optional absence versus empty/false/default. Owner backfilling cannot pass.

The shell adapter preserves preregister/spawn separation: a real parent
prepare_child prerequisite must not publish a task, then the actual installed
shell runs with full literal input and --prepare-only. Its own invocation must
publish the approved task and leave the sole owner unchanged before any helper.
Only then may existing foreground R2 deliver it, pinned to the prerequisite's
intent digest, without rerunning task preparation. Saved detached remains true;
ordinary detached/tmux and native behavior are not proven. Empty/nonempty MCP,
prepare-only, sixteen incoming-field differences and stale-pin checks are
separate controls. Native-off shell temporarily enables only its prerequisite;
the actual CLI interval must have zero replacements and real native refusal.

The dashboard adapter handles one actual authenticated HTTP request on the
invocation main thread, with only its client on a joined thread. Explicit fixture
setup configures a private capability; it is never placed in argv/env or capture/
trace output. Real admission/Handler/do_spawn/backend/operator/task calls must
share the same PID. The full nested request is always prepare-only; actual
status/body, task bytes/hash, identity/parent/phase and unchanged owner/digest are
checked before a separate TEST-only R2 foreground helper can run. That helper
uses task_prepared=True and the saved digest and cannot rescue a root no-op by
publishing a missing task. Ordinary HTTP foreground remains unsupported; saved
detached is not rewritten and ordinary detached/native behavior is not proven.
Empty/nonempty, prepare-only, sixteen literal differences and stale-pin controls
are separate. Native-off dashboard requires actual HTTP503 and real native-gate
refusal in the same admission/root PID with zero normal replacements.

Actual-entry no-op/stale controls cover all five named routes. Only explicit
negative mutants replace the selected real API method, actual CLI root or
dashboard.server.do_spawn in the invocation subprocess. The shell root
mutation waits for the exact installed __main__.main, changes only entry_operation,
records that single extra replacement and requires missing-task refusal before
R2 can run; it is not an internal task-helper stub. Independent literal method/file/
PID checks require both install and activation, the exact preparation/phase
failure, no current capture/witness and unchanged client tree. Normal binding
still replaces only the native gate. Stale mutants emit a prior actual capture
through the current script after real entry/R2 success, retain pre-run hash and
fresh driver/witness/PID checks, and must fail at the current nonce. Setup or
unrelated errors do not count. The dashboard mutant snapshots module function
identities, changes exactly do_spawn, and records its exact module/qualname/file/
PID, replacement name/count and actual HTTP activation. Its seedless control
requires missing task before any R2 helper; seed-dependent mutants blocked at
real ps do not count as detected. Oracle-only no-op matrices are not substitutes
for these actual-entry mutations or successful outside delivery evidence.

Only the literal `AGENTSTACK_LAUNCH_ID`, `AGENTSTACK_LAUNCH_NONCE`, and
`AGENTSTACK_PROVIDER_PID` differ between executions. Each is independently
checked against the real R2 `runtime/launch.json` or the capture process's own
PID before comparing every other environment key/value and the full argv.
Fresh capture paths/nonces and no-op controls remain mandatory.

Tools have three independent contracts: the `base=mail-only, tools={}` baseline
preserves bound Mail and shell configuration; a separate literal
`tools={"mcp":["fixture_extra"]}` matrix preserves a real fixture MCP selection
through all five entries; `mail`/`shell` selector tokens remain invalid. The
extra server is a fixture-owned definition, not a live MCP service. Captured
provider-home TOML and argv are checked independently of the saved selection.
This proves configuration preservation only, not native tool execution. The
oracle-only controls reject lost Mail/shell/MCP configuration and a caller that
silently saves an empty selection. Their synthetic binding never substitutes for
the incomplete real `caller_acceptance` binding; repeat the always-empty mutation
through real entries before claiming caller acceptance.

`test_real_tools_mutation.py` repeats the unchanged actual five-caller checker
with only the real TEST adapter's incoming tools dropped to `{}` before its
configure/entry calls. It restores the caller and adapter afterwards; it never
fabricates an owner, capture or receipt. Only the exact literal-tools assertion
after actual shell/R2/provider delivery counts as detection, with independent
gate/receipt/pre-run-hash checks. The checker stops at its first bad caller
(shell): this is one actual always-empty mutation, not five independent bad-entry
controls. Setup/ps failures remain failures, not mutation detection; successful
outside execution is required where process inspection is unavailable.

The bound Mail script must equal the literal absolute
`workspace.tmp/install/bin/lib/runtime_client.py` path, determined independently
from the fixed owner layout rather than the product resolver or adapter. The
installed regular-file bytes must match the checkout source. The Mail command
must equal `workspace.tmp/delivery-python/bin/python`; the venv uses regular
copies, with bytes checked against the original test Python's canonical
executable. Do not resolve an observed symlink alias and accept its target.
On Darwin non-framework shared builds, the same interpreter's sysconfig-declared
libpython is an additional regular copy in private venv/lib, checked against its
pre-copy digest and source bytes before probing and at each bootstrap. Framework
builds take the no-copy branch. Named metadata/resource/probe failures never
select another interpreter. The serial CI startup test logs the actual selected
branch; local framework/uv runs do not prove which build setup-python supplies.
Missing/same-suffix other-root, file/directory-symlink and wrong-bytes resources
are rejected for both selection matrices, as are another command and the
original host Python path. Real-entry rejection remains a later binding gate;
oracle controls alone do not establish it. The wire
peer likewise accepts only the bare fixture function name or its one exact
`mcp__fixture__fixture_echo` name, never an arbitrary same-suffix server name.

The fixed external-command driver retains one approved source path/digest
throughout all five callers. Its dispatch points only to a fresh checked script
inside the owned temporary `captures/` directory. A fresh driver witness binds
the script digest and unchanged PID to the capture. Before invoking each caller,
the oracle holds the expected script hash in a local value; both the post-run
script bytes and witness must match it, not a digest recomputed from a modified
dispatch. Dispatch and script file UID controls preserve the valid directory
and require rejection at the named resource's UID check. Separate directory-only
mode/UID/symlink controls require the directory rejection before any file or
execution evidence is produced. This is not evidence that
an actual Claude/Codex binary was started and does not replace production CLI
source-digest checks. The check-to-exec race is accepted only within this owned
temporary fixture root with 0500 scripts, not as a product security boundary.
